# 02. Project Architecture

Документ описывает назначение проекта, общий технологический стек и разделение ответственности между инструментами.

## 1. Назначение проекта

«Осколки Реальности» — сюжетная RPG с элементами расследования, мистики и психологического хоррора.

Игрок принимает решения, исследует мир, сражается с противниками и постепенно раскрывает устройство реальности.

Проект одновременно является:

1. игрой «Осколки Реальности»;
2. универсальным игровым движком для текстовых RPG, визуальных новелл и интерактивных историй.

Движок должен поддерживать:

- изображения;
- анимации;
- музыку;
- боевую систему;
- инвентарь;
- нелинейное повествование;
- систему сохранений.

## 2. Разделение проекта

Проект разделён на две независимые части:

- контент: история, сцены, персонажи, квесты;
- движок: игровая логика, состояние, условия, эффекты, сохранения.

Это позволяет разрабатывать игру и движок независимо друг от друга.

## 3. Главный архитектурный принцип

Twine отвечает только за сценарий.

JSON является форматом обмена.

NestJS отвечает за игровую логику.

Vue отвечает за отображение.

PostgreSQL хранит игровой мир и прогресс.

## 4. Общая схема

```text
Twine
↓
Narrative Parser
↓
JSON
↓
Import Service
↓
PostgreSQL
↓
NestJS API
↓
Vue Client
```

## 5. Twine

Twine используется исключительно как визуальный редактор истории и ветвлений.

Он отвечает за:

- написание истории;
- проектирование ветвлений;
- построение графа сцен;
- проверку логики повествования.

Twine не содержит игровую логику.

## 6. JSON

JSON является единственным форматом обмена между редактором контента и движком.

Движок не зависит от Twine. Twine используется только как источник данных для экспорта.

Все игровые данные должны быть сериализуемыми.

## 7. Backend

Backend реализуется на NestJS.

Он отвечает за:

- игровую логику;
- состояние игрока;
- применение эффектов;
- выполнение условий;
- боевую систему;
- квесты;
- сохранения;
- характеристики;
- экспорт и импорт сценариев.

## 8. Frontend

Frontend реализуется на Vue 3.

Он отвечает за:

- отображение сцен;
- диалоги;
- изображения;
- анимации;
- музыку;
- пользовательский интерфейс;
- получение данных от Backend.

Frontend не содержит игровую логику.

## 9. PostgreSQL

PostgreSQL является основным хранилищем.

После импорта игра работает с данными из базы.

База должна хранить:

- игровой контент;
- прогресс игрока;
- сохранения;
- состояние персонажа;
- квесты;
- инвентарь;
- отношения с NPC.

## 10. Основные игровые системы

Движок должен поддерживать:

- сюжетные сцены;
- диалоги;
- исследования;
- путешествия;
- боевую систему;
- инвентарь;
- характеристики персонажей;
- квесты;
- отношения с NPC;
- систему слоёв реальности;
- систему сохранений.

## 11. Основные цели движка

Создать универсальный Narrative Engine, поддерживающий:

- текстовые RPG;
- визуальные новеллы;
- интерактивные книги;
- детективы;
- хорроры;
- квесты;
- RPG с исследованиями;
- проекты с большим количеством ветвлений.

## 12. Правило независимости

Все элементы проекта должны быть независимыми друг от друга:

- Twine отвечает за повествование.
- JSON является универсальным форматом данных.
- NestJS отвечает за игровую логику.
- Vue отвечает за отображение.
- PostgreSQL хранит игровой мир и прогресс.

Такой подход позволяет масштабировать проект без переписывания архитектуры и использовать движок для других сюжетных игр.
