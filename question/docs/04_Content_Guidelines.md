# 04. Content Guidelines

Документ описывает правила создания игрового контента для «Осколков Реальности».

## 1. Сюжет отделён от логики

Twine описывает только структуру истории.

Игровые механики реализуются в движке.

В сценах нельзя напрямую реализовывать:

- расчёт боя;
- изменение характеристик без эффекта;
- работу инвентаря;
- сохранения;
- UI;
- анимации;
- внутреннюю backend-логику.

## 2. Каждая сцена имеет одну смысловую цель

Сцена должна описывать одно событие:

- разговор;
- исследование;
- бой;
- путешествие;
- выбор;
- катсцену.

Не следует объединять несколько независимых событий в одной сцене.

## 3. Ветки могут объединяться

Если несколько вариантов развития сюжета приводят к одному событию, используется одна общая сцена.

Различия описываются условиями и состоянием игрока, а не созданием множества почти одинаковых сцен.

## 4. Названия сцен являются техническими

Название сцены описывает её назначение, а не литературное название.

Примеры:

```text
l1_001_apartment_wakeup
l1_002_phone_call
l1_020_street_ambush
```

## 5. Игровое состояние хранится отдельно

Все характеристики, флаги, предметы, отношения и прогресс игрока находятся в Game State.

Сцены не должны содержать информацию о текущем состоянии игрока как постоянные данные.

## 6. Рекомендуемая структура идентификатора сцены

```text
l{layer}_{number}_{location}_{event}
```

Пример:

```text
l1_001_apartment_wakeup
```

Расшифровка:

- `l1` — слой реальности;
- `001` — порядковый номер сцены;
- `apartment` — место;
- `wakeup` — событие.

## 7. Что должно быть у сцены

Минимальная сцена должна иметь:

- стабильный `id`;
- `type`;
- опциональный `subtype`;
- текст или ссылку на текст;
- список переходов;
- опциональные условия;
- опциональные эффекты;
- теги.

Пример черновой структуры:

```json
{
  "id": "l1_001_apartment_wakeup",
  "type": "story",
  "subtype": "intro",
  "tags": ["layer1", "night", "story_critical"],
  "content": [
    {
      "type": "paragraph",
      "text": "Ворон открывает глаза в тёмной комнате."
    }
  ],
  "choices": [
    {
      "id": "choice_explore_room",
      "text": "Осмотреть комнату",
      "target": {
        "type": "scene",
        "sceneId": "l1_002_apartment_explore"
      }
    }
  ],
  "enterEffects": [
    {
      "type": "set_flag",
      "flag": "intro_started",
      "value": true
    }
  ]
}
```

## 8. Правила выбора типа сцены

Тип сцены выбирается по игровой функции, а не по настроению.

Примеры:

| Ситуация | Тип |
| --- | --- |
| Ворон просыпается и вспоминает прошлое | `story` |
| Разговор с NPC | `dialogue` |
| Осмотр квартиры | `exploration` |
| Поездка к базе Хранителей | `travel` |
| Засада культистов | `combat` |
| Видение без выбора игрока | `cutscene` |
| Невозвратное решение | `choice` |
| Финал ветки | `ending` |

## 9. Правила для AI-агентов

При генерации контента AI обязан:

- не нарушать архитектуру проекта;
- использовать принятую систему именования сцен;
- использовать только утверждённые типы сцен;
- не создавать дублирующиеся сцены без необходимости;
- не помещать игровую логику в Twine;
- использовать DSL проекта после его утверждения;
- соблюдать единый стиль повествования;
- проверять новый контент по World Bible.

## 10. Стиль повествования

Стиль игры:

- мистика;
- расследование;
- психологический хоррор;
- мрачная городская атмосфера;
- постепенное раскрытие устройства реальности.

Главный герой не должен ощущаться новичком. Ворон — опытный Хранитель, который уже знает часть правил мира.

Напряжение строится не только на опасности, но и на цене знания, последствиях решений и нестабильности реальности.

## 11. Что нельзя делать в контенте

Нельзя:

- делать демонов свободно живущими на Земле;
- раскрывать существование слоёв большинству обычных людей без последствий;
- нарушать правило девяти слоёв;
- превращать Печати в обычные заклинания;
- делать Хранителей публичной организацией;
- создавать сцены-дубликаты ради мелких различий;
- привязывать контент к конкретной реализации backend-кода.

## 12. Открытые вопросы

Эти темы нужно оформить отдельными документами:

- формат условий;
- формат эффектов;
- система квестов;
- система боя;
- система отношений с NPC;
- формат экспорта из Twine;
- правила возврата из переиспользуемых сцен.
